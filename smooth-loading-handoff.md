# Smooth loading implementation

Both courses now prepare screens, questions and required tools through one coordinator before committing. The outgoing screen stays visible and inactive; a single 3px teal bar appears after 200ms and stops immediately when ready. Initial HTML supplies the dark branded screen before React. The reduced-motion bar is static. Routes, headers and course state commit together; stale requests cannot publish, and prepared resources are disposed.

The coordinator freezes commands and timing synchronously, drains started writes, and awaits durable same-attempt restoration before Cancel or Reload can complete. A newer intent supersedes recovery safely. Curriculum/teacher tools, Recall Test/Flashcards/autostart, statistics refresh, import and all three Olympiad activities use this interface. Teacher and challenge evidence remain isolated.

Ordinary read/write errors offer Retry and Cancel. A browser may cache a failed JS module or CSS preload permanently for the current document. Those classified failures offer **Reload app** and Cancel. Reload passes the durable save/resume gate and restores the committed route and saved attempt; the user repeats the requested navigation. No arbitrary cache-busting imports were introduced. Actual failed fetch and denied-session-write browser checks verify this behavior without duplicate evidence.
